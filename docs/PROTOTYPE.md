# FlowVoice 原型使用与验收手册

当前阶段：第一个里程碑的开发原型。目标是验证「录音 → 语音识别 → 可选润色／写作 → 预览或输入原应用」的流程。产品路线和长期架构见 [开发手册](DEVELOPMENT_MANUAL.md)；本文件只描述当前代码已经提供的能力。

## 1. 当前实现

| 部分 | 实现与边界 |
| --- | --- |
| 桌面与界面 | Tauri 2 + Rust；Vite + React + TypeScript；Zustand 状态；Tailwind 与手写样式／组件 |
| 录音 | 系统默认麦克风，CPAL 采集；单次最多 120 秒；可取消；音频保留在内存，不保存原始录音文件 |
| 本地 ASR | sherpa-onnx + SenseVoice Small INT8，CPU 推理，模型在首次识别时加载并缓存 |
| 云端 ASR | OpenAI 兼容的 `POST /audio/transcriptions`，上传单声道 PCM WAV |
| 本地 LLM | 连接用户已经启动的本机 OpenAI 兼容服务；当前不内嵌、下载或启动 llama.cpp／Ollama |
| 云端 LLM | OpenAI 兼容的 `POST /chat/completions`，用于口述润色和按要求生成内容 |
| 桌面交互 | 全局快捷键、托盘、录音浮窗、结果编辑与复制、macOS／Windows 原生输入适配 |
| 设置与凭据 | 普通设置保存到应用配置目录；ASR／LLM 密钥分别存入 macOS 钥匙串或 Windows 凭据存储 |

本地 SenseVoice 在录音中持续更新当前半句，按停顿确认语句并追加到**同一词条**；半句允许修正，最终文本在同一词条中完成。当前采用离线模型重复分段识别，不是原生逐 token 流式模型。通用云端转写仍是松开后的整段识别，润色和生成也在完整文本后返回。支持的是指定协议的兼容服务；每家服务商的专有流式协议仍需单独适配。

## 2. 开发环境与启动

先准备 Node.js、pnpm、Rust。当前原型将 macOS 最低版本设为 **13.3**，与 Tailwind 4 和当前 Vite 默认构建的 Safari 16.4 基线对齐；这项配置仍需在对应系统实测。版本依据见 [Tailwind 兼容性说明](https://tailwindcss.com/docs/compatibility) 与 [Tauri WebView 版本表](https://v2.tauri.app/reference/webview-versions/)。

macOS 开发需要 Xcode Command Line Tools；Windows 需要 Microsoft C++ Build Tools、Windows SDK 和 WebView2。系统依赖及安装步骤以 [Tauri 官方前置要求](https://v2.tauri.app/start/prerequisites/) 为准。

当前开发用 Mac 已通过 rustup 安装 Rust，但没有修改用户终端启动配置。每个尚未加载 Rust 的终端会话先运行：

```sh
source "$HOME/.cargo/env"
```

进入仓库根目录后：

```sh
pnpm install
pnpm tauri dev
```

Windows 在安装 Rust 后重新打开 PowerShell，再执行上述两条 `pnpm` 命令；不要执行 Unix 的 `source` 命令。首次构建会下载 npm／Cargo 依赖和推理运行库，耗时取决于网络与机器配置。

开发窗口启动后，关闭主窗口会隐藏到托盘；通过托盘可以重新打开、取消当前任务或退出应用。全局快捷键冲突会显示提示，可以在「偏好设置」修改。

`pnpm dev` 只启动浏览器界面预览。浏览器中的录音、模型下载、系统权限和全局快捷键均不代表桌面功能可用。

## 3. 首次配置模型

### 3.1 本地语音识别

1. 打开「模型服务」，在语音识别中选择「本地模型」。
2. 点击「下载 SenseVoice 模型」，或选择已有模型目录。
3. 导入目录必须包含 `model.int8.onnx` 和 `tokens.txt`；此版本只接入 SenseVoice Small INT8，不支持随意替换其他 ONNX 模型。
4. 保存模型设置，回到工作台，选择「实时输入」。

内置下载约 240 MB，使用固定版本和 SHA-256 校验，下载到应用数据目录中的 `models/sensevoice-small-int8`。网络失败时可以重新下载或导入本地目录。目录显示“已就绪”表示必需文件存在；模型是否可以加载仍由首次推理确认。

模型准备完成后，本地 ASR 不需要联网。若同时使用云端 LLM，识别得到的文字仍会发送到选定的语言模型服务。

### 3.2 云端语音识别

选择「云端服务」，填写服务商的 API Base URL、模型 ID 和 API Key，然后保存。Base URL 通常类似 `https://api.example.com/v1`；程序会追加音频转写路径。

当前请求协议为 multipart：包含 `file`、`model` 和 `response_format=json`；响应需要包含非空的 `text` 字段。录音只发送到明确选择的 ASR 服务。转写失败不会自动切换另一家服务。

不支持该协议的厂商，需要后续新增适配器。远程服务地址必须使用 HTTPS，密钥不能放在 URL 中。

### 3.3 润色与写作

「暂不使用」语言模型时仍可进行实时输入；「润色改写」与「帮我写」需要启用语言模型。

| 方式 | 配置 |
| --- | --- |
| 本地服务 | 先自行启动兼容服务，再填写如 `http://127.0.0.1:8080/v1` 的地址和实际模型 ID |
| 云端服务 | 填写服务的 HTTPS Base URL、模型 ID 和 API Key |

本地服务地址仅接受 `localhost`、`127.0.0.1`、`[::1]` 等本机回环地址，当前不把局域网服务器归为本地模式。兼容接口需接收 `model`、`messages`、`stream=false`，并返回 `choices[0].message.content` 字符串。

可以从工作台口述后处理，也可以直接将文字粘贴到结果编辑框，点击「润色文字」或「根据要求写作」。当前不读取其他应用选中的文字；需要引用前文时，请自行将前文和要求一起粘贴或口述。

工作台默认没有空白编辑框；点击「手动输入」后会新增一条记录，可以粘贴或编辑文字。记录仅保留在本次运行中，刷新浏览器预览或重启应用后不会恢复。

API Key 输入框留空时保留当前服务已保存的密钥；密钥不会写入普通设置 JSON 或浏览器存储。凭据按 ASR／LLM 用途、本地／云端模式及规范化后的服务端点分别绑定，端点摘要使用 SHA-256。同一端点更换模型 ID 可以复用密钥；切换到其他服务或模式不会带入原服务的密钥。当前仍没有用于保存、命名和切换整套模型设置的多配置库。

## 4. 录音与输入

Windows 默认快捷键为 **Ctrl + Shift + Space**，macOS 为 **Option + Shift + Space**。按住快捷键开始录音，松开后结束并处理；也可以在录音浮窗或工作台手动停止。录制自定义快捷键时使用用户实际按下的修饰键，Windows 不再显示 Mac 专属符号。macOS 设置页保留辅助功能权限入口；Windows 使用系统输入接口，不显示该 macOS 权限面板。到达 120 秒后会停止录音并处理。录音、识别或生成期间可以取消；取消后不应再把该任务的迟到结果写入其他应用。已经发出的网络请求或已开始的本地推理不一定立即终止，取消不代表撤回已发送的数据。

点击工作台麦克风开始录音时，只在工作台显示结果。需要自动输入时：

1. 选择「实时输入」，在「偏好设置」启用自动回填。
2. 将光标放在外部应用的文本输入框中。
3. 按住全局快捷键录音，期间保持原输入位置；松开后结束录音。
4. 检查原应用是否收到文字；工作台仍保留结果供编辑或复制。

润色和生成内容先在工作台预览。自动输入使用原生 Unicode 事件，不通过临时替换剪贴板工作；只有点击「复制」才会写入剪贴板。

自动输入会重新核对原目标。目标变更、权限不足、修饰键仍按下、结果超过 8,000 个 UTF-16 单元，或文本含换行、Tab 等控制字符时，会保留结果供手动复制。程序不自动发送 Enter，避免触发聊天发送或终端执行。

本地实时输入在约 0.6 秒停顿后确认一段语句，并只向原输入框追加这段新文字。当前半句不会自动模拟退格修正；长句仍在识别时，最终措辞可能变化。快捷键尚未松开时，确认语句也可通过清除修饰键的 Unicode 事件追加。取消或焦点变化会阻止后续自动输入，已经发送的文字不会擅自删除。

macOS 会比较前台进程及辅助功能提供的聚焦元素／窗口；Windows 会比较进程、前台窗口和聚焦子控件。部分应用不提供完整焦点信息，浏览器内不同编辑元素也不一定对应不同 HWND。系统事件没有目标编辑器的接收回执，因此“已提交输入”仍需目视检查。输入中途切换焦点时可能已经写入部分文字；请先检查原输入框再复制完整结果，避免重复。

## 5. 权限与常见问题

| 现象 | 处理 |
| --- | --- |
| Mac 无法录音 | 在系统设置的「隐私与安全性 → 麦克风」允许当前运行程序；确认系统默认输入设备可用。开发运行与打包应用的权限主体可能不同 |
| Mac 不能自动输入 | 在偏好设置请求辅助功能权限，再到「隐私与安全性 → 辅助功能」开启对应程序；必要时重新启动。拒绝该权限仍可使用预览与复制 |
| Windows 无法录音 | 检查系统麦克风隐私设置以及“允许桌面应用访问麦克风”，确认默认输入设备 |
| Windows 不能输入到管理员窗口 | 系统 UIPI 会限制普通权限应用注入高权限窗口；在结果区手动复制，由用户自行粘贴 |
| 快捷键没有响应 | 检查页面提示是否注册失败，尝试修改快捷键并保存，排除其他软件占用 |
| 模型目录已选但识别失败 | 确认目录中的两个文件对应同一版本的 SenseVoice Small INT8；重新下载可以校验内置模型完整性 |
| 本地 LLM 连接失败 | 确认服务已经运行、端口与模型 ID 正确，并提供兼容 Chat Completions 接口 |
| 云端报错 | 核对 Base URL、模型 ID、密钥、服务额度和接口协议。不会自动换用别的模型 |

仓库包含 macOS 麦克风用途说明与音频输入 entitlement。它们不等于已经取得系统授权，也不等于应用已签名、公证或完成商店发布。

## 6. 检查与验收

在仓库根目录运行：

```sh
pnpm build
pnpm test
pnpm test:e2e
cargo test --manifest-path src-tauri/Cargo.toml
```

首次运行浏览器检查可能需要先执行 `pnpm exec playwright install chromium`。构建本机可打开的 macOS 开发包：

```sh
pnpm tauri build --debug --bundles app --no-sign --ci
```

生成位置是 `src-tauri/target/debug/bundle/macos/FlowVoice.app`。这是本机调试包，不是已签名、公证的正式分发版本。

`pnpm build` 执行 TypeScript 检查和 Vite 生产构建，仅验证前端产物。Rust 单元测试覆盖音频转换、Unicode 分块、输入字符约束、请求协议及设置逻辑等；真实模型测试需要额外准备模型和音频样本。构建或测试通过都不能代替麦克风、快捷键、权限和跨应用输入的实机测试。

原生模块已经在 macOS 完成独立编译及 5 项单元测试。整应用也已通过 Windows x64 GNU 目标的交叉类型检查；这不代表 Windows 完整桌面应用已经运行成功。正式 Windows 构建应在 Windows 上使用默认 MSVC 工具链执行 `pnpm tauri build`。整应用的后续验证记录应写明平台、命令、测试输入和实际结果，不从模块测试推导验收结论。

建议按以下顺序手工验收，先在空白本地文档或测试输入框中操作：

| 场景 | 预期结果 |
| --- | --- |
| 工作台录制一句中文 | 电平和时间变化；结束后显示完整转写，其他应用没有文字输入 |
| 外部编辑器快捷键录音 | 录音浮窗不抢焦点；本地确认语句逐句追加，结果区保留同一份文字 |
| 录音后切换应用／窗口 | 自动输入停止或跳过，结果保留并说明原因 |
| 录音中取消；识别中取消 | 麦克风停止或任务失效；迟到结果不自动插入 |
| 润色或按要求写作 | 保留原始转写，结果先预览；可编辑和复制 |
| 多行文本、长文本、emoji | 多行／超限文本保留预览；符合条件的 Unicode 不拆代理对 |
| 模型缺失、断网、错误密钥 | 显示可理解错误，不自动回退到别的云端服务；已有转写尽可能保留 |
| 本地模型准备完毕后断网 | 本地 ASR 可工作；全本地组合还需本机 LLM 服务已启动 |
| 复制与自动输入 | 自动输入前后剪贴板不变；显式复制按用户操作更新剪贴板 |
